- [x] Wire the shopping-flow redesign mockups (Products, Product Detail, Cart, Checkout) into real components — sidebar active-state highlight and illustrated error/empty states on Products, trust badge + stock status on Product Detail, a polished dashed-border empty state on Cart, and a step indicator (Delivery Details → Payment) plus a receipt-style order summary on Checkout. Verified with mocked API data via Playwright at desktop and mobile widths.
- [x] **Bonus fix (found while restyling `ProductCard.css`):** `.product-price` was hardcoded to `color: var(--white)` with no theme guard — **price text was invisible on the light theme's white card background** across every product card in the app. Also `.product-badge` used an undefined `--gold` CSS variable (no fill), and several other rules (`--cream`, `--dark-3`, `--gold-light`) were undefined and silently falling back to inherited values. Rewrote using real, defined tokens (`--accent`, `--text`, `--surface-2`).
- [x] Finish the undefined-CSS-variable cleanup — checked all four originally-flagged files: `Newsletter.css` and `TrendingDeals.css` turned out clean on closer inspection (that earlier note was too broad); the real remaining offenders were `CartDrawer.css` and `Features.css`. **`CartDrawer.css` had the same invisible-text bug as `ProductCard.css`** — "My Bag (N)", the quantity numbers, and the subtotal were all hardcoded to `var(--white)`, invisible on the light theme's white drawer background (the cart drawer opens on every "add to cart" click, so this was a frequently-hit bug). `Features.css` had a half-finished light/dark theming migration: a working `[data-theme="light"]`-scoped ruleset coexisted with dead legacy rules using `var(--dark)`, `var(--dark-2)`, `var(--dark-3)`, `var(--gray-1)` (all undefined, shadowed by the higher-specificity light rules so mostly harmless) — except two that weren't shadowed and were genuinely broken: the `<span>Glow</span>` gradient-clip heading text was fully invisible (`var(--gold)` undefined), and the `.feature-card` hover accent line likewise. Consolidated both files into single theme-aware rulesets using real tokens (`--text`, `--text-muted`, `--accent`, `--surface`/`--surface-2`), removing the dead duplicate rules. Verified with a full sweep: every one of the 42 distinct CSS custom properties referenced anywhere in `client/src` now resolves to a token actually defined in `index.css` (0 undefined). Confirmed the `CartDrawer` fix visually via Playwright (light theme: heading/quantities/subtotal all render correctly now). **Found but out of scope:** `Features.jsx`/`Features.css` aren't rendered anywhere in the app — dead, orphaned code; left in place since deleting a whole component wasn't asked for.

## Next

- [x] Add request-body validation — done with `zod`. A `validate(schema)` middleware (`server/middleware/validate.js`) parses `req.body` against a per-route schema in `server/validators/` and returns a structured 400 on failure; wired into all 11 route files that accept a body (auth, orders, admin, contact, loyalty, reviews, recommend, routine, search, skin-analysis, wishlist). Removed the now-redundant manual `if (!x) return 400` checks those schemas replace. Covered by `tests/validation.test.js`.
- [x] **Bonus fix (found while validating admin product fields):** `adminController.js`'s create/update product and `AdminDashboard.jsx`'s product form both used `countInStock`, but the `Product` schema's field is `stock` — Mongoose silently dropped it, so admin-set stock never persisted (new products always got the schema default). Renamed to `stock` consistently.
- [x] Add structured logging — done with `pino`. `server/utils/logger.js` exports a configured instance (pretty-printed in dev, JSON in production, silent in tests); `pino-http` is wired into `app.js` so every request gets a log line for free. Converted all ~90 `console.log`/`console.error`/`console.warn` calls across `app.js`, `server.js`, every controller, `middleware/errorMiddleware.js`, both queue files, and both services to structured `logger.info`/`.warn`/`.error` calls. Left the one-off CLI scripts (`setAdmin.js`, `setProdAdmin.js`, `checkAdmin.js`, `data/seeder.js`) on plain `console.log`, since that's the right tool for a script a developer runs and reads directly in a terminal. Also deleted `sendWhatsAppNotification` in `orderController.js`, a dead helper that was never called (WhatsApp actually goes out via the queue). `config/db.js`'s fatal-exit path calls `logger.flush()` before `process.exit(1)` so the error line isn't lost to pino's async dev transport — verified directly.
- [x] Add a staging environment, separate from production — code/config side done: a `gracia-fab-api-staging` Render service alongside production in [server/render.yaml](../server/render.yaml), CI (`ci.yml`) now gates the `staging` branch the same as `main`, and [DEPLOYMENT.md](DEPLOYMENT.md) documents the full setup. **Still needs manual, one-time dashboard work by whoever holds the accounts** (no API access to Render/Vercel/MongoDB Atlas/Redis from here): create the `gracia-fab-staging` MongoDB database, a second Redis instance, Paystack test-mode keys, the Render staging service's env vars, and a stable Vercel alias for the `staging` branch — all spelled out step-by-step in DEPLOYMENT.md.
